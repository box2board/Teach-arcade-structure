# Public feature blocker pilot
This isolated main-based branch contains a routing middleware pilot for RV Road Trip Mayhem, Chess and Sudoku. Their availability is unchanged unless TA_FEATURE_GATE_ENABLED=1. Use preview-only environment settings first; never enable production until reviewed. The pilot uses a read-only Vercel Edge/Global Config item named teach_arcade_pilot. Set its value to {"brain-rv-road-trip-mayhem":"live","brain-chess":"live","brain-sudoku":"live"} before enabling; TA_FEATURE_CONFIG_URL is the item endpoint URL with a scoped read token (server-only), not the management API token. A valid configuration is required after activation; unavailable config fails closed for pilot routes only. Changes to the item are runtime reads; verify provider propagation and latency in preview. No secrets belong in Git.
Supported pilot statuses: live, coming_soon, under_improvement. Beta and hidden are not implemented. Tiles retain existing artwork and link to the informational landing page. Blocked game routes return a non-cacheable 503 preview; non-document game files receive 403 or 503. Existing open tabs/cached copies cannot be remotely revoked. This is availability management, not DRM or protection for public Git source. Route matcher and encoded URL normalization need real Vercel HTTP tests.
Before approval: install/build; run npm run test:feature-gate and full existing build; verify matcher on Vercel for /game, /game/, /game/index.html, encoded and case variants, asset paths, query strings and alternate domains; test GET/HEAD, stale caches, flag changes, outage, and unrelated games; measure latency. No public admin bypass yet; use a separate protected development deployment with gate disabled for owner testing. Extend shared discovery surfaces (home, Teacher Cabinet, site search) before general release. Multiplayer create/join and mini-game embedding require their own server checks; no changes here.
HQ decision registry remains separate; publish adapter, confirmed target configuration, actual vs desired status and authorization/audit still need integration. No production or preview was manually deployed, no config was provisioned, no feature was blocked by this commit.
