# Teacher account deletion

Development preview only. Account → Delete my teacher account requires a sign-in within 15 minutes, typing DELETE, and a final browser confirmation. A session refresh does not reset the 15-minute window.

POST /api/teacher?action=delete-account validates Origin, confirmation, and Auth identity. The authenticated teacher JWT calls public.delete_teacher_account, an invoker wrapper for a narrowly scoped private definer function. No service-role key is added. The private function derives the target from auth.uid(), checks the JWT session_id against a recent, live auth.sessions row belonging to that teacher, deletes their sessions and authentication user in one transaction. Cascading foreign keys remove the teacher profile, original sets, saved shortcuts, and submitted reports. Original sets also lose their references in other teachers' saved shelves. Independent copies remain. Existing issued JWTs can persist until expiry, but no longer have a live auth session or parent teacher record; the website also verifies identity with Auth on requests.

The UI never invokes deletion on page load, normal sign-out, or opening the disclosure. Failure leaves the user signed in and displays an error. Successful deletion clears both HttpOnly cookies and in-memory collections. This is irreversible in normal product use. Backups and provider operational logs have their own retention and are not claimed to be erased by this operation. No uploaded account-owned Storage objects currently exist; revisit object cleanup before adding teacher uploads.

Rolled-back development SQL tests use temporary users to verify stale/wrong sessions cannot delete, fresh sessions clean up account data, repeated calls fail, anonymous users cannot call it, and the other teacher's content survives. No actual teacher account was deleted during testing. Browser QA must stop before final deletion unless the user explicitly authorizes deleting the selected account.
