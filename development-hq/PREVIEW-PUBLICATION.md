# Preview publication bridge
Separate from production. HQ registry decisions remain draft until the admin confirms the exact preview snapshot. This bridge only supports the three mapped pilot games. It reads and patches a single key teach_arcade_pilot in a dedicated Edge Config store with exact slug teach-arcade-blocker-preview, validates the target metadata, refuses unsupported statuses, verifies current config and decision revisions, reserves an audit slot, and reads the config back. No automatic retry of uncertain operations. A verified config update is not a verified website request.

Setup: verify actual Vercel project/team and preview deployment, create a separate preview-only store with all three keys set to live, configure the public pilot preview with read-only token and TA_FEATURE_GATE_ENABLED=1, and configure the HQ deployment with server-only DEVHQ_PREVIEW_* values. Use a least-privilege management credential where supported. Never link this store to public production; production must use a separate store and separate release workflow. Apply 004 and 005 to the dedicated HQ Neon database with approval. Test admin login, registry import, publication, actual preview route responses, cache propagation, latency and rollback. Do not select statuses for the user. The store must have a single writer; REST patch has no cross-system transaction or demonstrated compare-and-swap, so external writers are prohibited. If pending or uncertain, inspect config and deployment, reconcile audit manually with documented evidence and explicit approval before clearing the lock; do not blindly retry.
